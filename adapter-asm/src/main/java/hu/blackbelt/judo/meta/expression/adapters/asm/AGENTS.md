# `adapter-asm/src/main/java/hu/blackbelt/judo/meta/expression/adapters/asm` — binds expression metamodel to Ecore/ASM elements plus the measure metamodel

| File | Purpose |
|---|---|
| `AsmMeasureProvider.java` | Serves `Measure`/`Unit` instances of the measure metamodel out of a runtime measure `ResourceSet`. Implements `MeasureProvider<Measure, Unit>`; exports `getMeasure(namespace, name)`, `getMeasures()`, `getUnits()`, `getUnits(Measure)`, `getBaseMeasures(Measure)`, `getUnitByNameOrSymbol(Optional<Measure>, nameOrSymbol)`, `isBaseMeasure`, `isDurationSupportingAddition(Unit)`, `setMeasureChangeHandler(MeasureChangedHandler)`, package-private `getMeasureElement(Class)`. `getBaseMeasures` expands a `DerivedMeasure` into its `terms` as base-measure→exponent `EMap`, and returns a singleton `{measure: 1}` for a `BaseMeasure`. `getUnitByNameOrSymbol` with an empty measure searches all measures and throws `IllegalStateException("Ambiguous unit symbol, more than one measure contains …")` when two measures share the symbol — pass the owning `Measure` to disambiguate. `isDurationSupportingAddition` is true only for `DurationType` `MILLISECOND`..`WEEK`; `MONTH`/`YEAR` are excluded on purpose. `setMeasureChangeHandler` attaches an `EContentAdapter` to the `ResourceSet` and fires `measureAdded`/`measureRemoved`/`measureChanged` (the latter on `DERIVED_MEASURE__TERMS`); repeated calls stack adapters, they are never removed. `getMeasureElement` streams `resourceSet.getAllContents()` in parallel on every call — no caching. |
| `AsmModelAdapter.java` | Implements `ModelAdapter` over Ecore: resolves expression `TypeName`/`MeasureName` to `EClassifier`, `EClass`, `EAttribute`, `EReference`, `EEnum`, `EDataType`, and reads derived/measured metadata from ASM extension annotations. → see `AsmModelAdapter.AGENTS.md` |
| `ExpressionValidatorOnAsm.java` | Runs expression-model validation against a concrete `AsmModel` + `MeasureModel`. Exports two static `validateExpressionOnAsm` overloads — `(Logger, AsmModel, MeasureModel, ExpressionModel)` and `+ (Collection<String> expectedErrors, Collection<String> expectedWarnings)` — delegating to `ExpressionValidator.validateExpression` with a freshly built `AsmModelAdapter(asmModel.getResourceSet(), measureModel.getResourceSet())` and model aliases `"ASM"` and `"MEASURES"` bound to the two resources. Those alias strings are what the EVL scripts reference; renaming them breaks every script. Unexpected diagnostics raise `ExpressionValidationException`; the 4-arg overload passes `emptyList()` for both expectations, so any error or warning fails. |
